# Magpie

Vignette Radar is Magpie now. Magpie is a badass name and fits this addon perfectly: it finds rares, treasures, and every other shiny thing Blizzard lets us see.

Your settings and keybindings come with you. Use `/magpie`, or keep using `/vr`.

Magpie watches the rares, treasures, events, and other vignettes WoW exposes on the minimap and world map. You can also show saved locations from one chosen HandyNotes pack or Zygor POIs. Those notes are clearly marked and never count as live detections.

The small draggable launcher covers 150 yards. Its live radar lens, connected readout, and outline use the selected theme. Click it to grow into the rounded main radar. Use the minus control to return to the launcher; × turns detection off. Existing characters move to this main view on first load after updating. In WoW's **Key Bindings → AddOns → Magpie**, **Hold to raise launcher** brings the launcher in front of other UI while you drag it. If it disappears behind another UI element, `/vr recenter` brings it back into view.

Hover over the radar and click its corner settings icon to open **Radar Settings**. Its twelve compact tabs include **Wayfinding**, **Map Data**, and **Status**. Use **Find** in the title bar to search settings. The Guides tab adjusts ring visibility, yard text, facing cues, and the animated sweep. **Ring Visibility** changes the rings alone; **Radar Border Visibility** lives in Themes. The Themes tab offers 32 palettes in a two-row scroll area, plus a color picker for each radar element and marker type. Turn off **Use Icons** to display category-colored dots. The Performance page shows drawing costs by layer and automatically slows an expensive layer until it recovers. Popups close when you click elsewhere, press Escape, or use their close buttons.

In **Map Data**, choose **Auto**, **Off**, one installed HandyNotes data pack, or **Zygor POIs** when Zygor is installed. The picker lists only enabled packs with notes for your current map, parent zone, or continent. **Auto** chooses one pack as you travel, preferring a pack named for the current zone or expansion (such as Draenor) over a generic travel guide; otherwise it favors the closest map and then the pack with more notes. It keeps a comparable choice stable within the zone. Right-click a pack to use it only on this map while leaving other maps on Auto; **Clear this zone's choice** removes the override. Left-click still chooses a pack globally. The radar reads the pack's world-map locations, then shows only nearby ones inside its own range. A manual choice stays saved but shows no notes outside its covered zones. Filter treasure, mob, item, cave-entrance, and other-note locations independently. Notes default to small hollow dots colored by type. Turn on **Pack icons** to display the selected pack's own artwork, including its crop and tint when supplied; nodes without a usable icon remain hollow dots. Hover a note for its name, source, type, and distance. Numeric `{npc:ID}` labels resolve to the creature's name when the client provides it. These are possible saved locations, not currently detected spawns, and never trigger live alerts or appear in the live target picker. A matching live rare or treasure marker replaces a nearby saved note so the live detection stays clear. New installations default to **Auto**; an existing **Off** choice stays off until you select Auto. It works without HandyNotes installed. RareScanner does not expose its full location database through the HandyNotes plugin API. Zygor POIs is a separate, manually selected source of its loaded rare and treasure points; Auto continues to choose HandyNotes packs.

**World Focus** places one real Blizzard waypoint when you click a live rare, treasure, quest diamond, quest-start badge, or saved note. Use Markers → World Focus to cycle available points and control automatic arrival, radius, saved-note candidates, and optional Zygor guide-step dots. HandyNotes packs that expose a linked treasure path can guide through its entrance and intermediate coordinates before the treasure; **Next Route Step** advances manually. Auto Route can pause and resume without losing its visited stops. Right-click its radar button for five illustrated route choices: Closest, Rare, Treasure, Quest, and Zygor. The current choice is outlined, with a quieter outline while paused. Closest compares eligible live rares, treasures, quest objectives, and available quest starts; nearby-zone quest points are added gradually. Near ties prefer Rare, then Treasure, then Quest. It keeps each type's normal completion rule, follows linked treasure approach steps, and checks periodically for new points when none remain. Quest Auto Route starts at the closest mapped objective or available quest start. It keeps that stop pinned until the objective completes or the quest is accepted, then chooses the closest known quest location, including nearby zones. Radar Settings → Auto Route → Quest Routing has separate switches for closest-next-objective selection, available quest starts, and nearby-zone continuation; all three default on. Remote maps are read in small, cached batches rather than on every frame. **Previous Step** revisits a recorded quest point only while that point still appears in current quest data; **Next Step** returns to the forward point or moves to the next available one. Both actions have assignable hotkeys under WoW Key Bindings → AddOns → Magpie; you can bind Left/Up to Previous and Right/Down to Next. **Skip Stop** and **Skip Quest** handle objectives without usable map data. Its right-click menu also offers **Clear Focus**. Rare routes keep the current rare pinned on arrival and advance only after a recorded kill/clear or an explicit Skip Stop. For rare routes, the selected 10, 20, or 40-yard radius determines how close you must be for the recorded clear to advance the route. Treasure routes, including linked approach steps, advance within 3 yards; looting the nearby, matching game object can also advance a treasure stop before you reach it. Quest routes advance on objective completion or quest turn-in, not proximity. Looting another creature or container does not advance it. Zygor POI locations use our colored dots by default. Shift-click a Zygor POI to open its native step-by-step guide. Map packs without explicit path metadata show ordinary locations; the addon does not invent cave routes.

An active Auto Route shows a movable, neutral crystal chevron that turns smoothly toward its current stop. A compact readout shows Now and Next, plus the current stop's type, step progress, and distance. The radar's small arrow button toggles it; right-click the arrow for Auto Route settings. Click the pointer to expand a three-stop route horizon with **Lock Stop** and **Skip Stop** controls. **Highlight Active Destination** marks the selected point without an animated area; a focused quest is outlined at its diamond. The widget hides while the route is paused or waiting for another quest objective. **Reset Positions** or `/vr recenter` restores its initial position.

For Zygor's active guide, open **Radar Settings → World Focus → Zygor** or right-click **Auto Route → Zygor**. Choosing Zygor starts following and pins the selected objective, then opens the picker to choose another mapped objective or the next travel stop. **Follow Active Guide Automatically** can also be enabled in settings. It updates the waypoint when Zygor changes steps or goals; reaching the location alone does not complete a guide goal. A manually selected waypoint pauses follow until you resume it. The radar shows the current guide and pause control when you hover the route button. The guide picker explains when the active step has no mapped location. These controls work even when optional guide-step dots are hidden.

When you focus a waypoint or change an automatic route, a small themed note appears below the visible radar (or its launcher) and fades after a few seconds. It shows the selected Zygor objective, map-note text when available, route state, or the next step. If the radar is at the bottom edge of the screen, the note appears above it so it stays readable.

Treasure loots now save a small, account-wide log of where you stood when a matching game-object loot slot cleared. It works for live treasure detections and the currently selected HandyNotes or Zygor POI pack, even without an active route. Radar Settings → Status shows the observation count. Each treasure keeps at most three XY observations, and the log keeps at most 256 treasures. These are player-at-loot observations, not exact treasure centers or height measurements, so they do not silently move map pins or change the world waypoint altitude.

Turn on **Hide cleared** under Map Data or **Hide cleared rares + treasures** under Behavior to suppress cleared live detections and saved rare/treasure locations. Blizzard's completed reward-quest flags keep eligible locations hidden until their daily, weekly, or one-time completion state resets. A vignette that Blizzard marks as dead hides its matching rare or treasure location for one hour. Right-click a saved rare or treasure note to hide that specific location for an hour when this setting is on. Locations without an exposed completion flag or dead-vignette state remain visible; the addon does not guess loot eligibility. The filter is off by default. Midnight does not allow addons to observe combat-log kills.

The rounded radar is the main view. Hovering reveals zoom, focus, legend, settings, orientation, trail, Auto Route, mini arrow, visibility, help, minimize, and close controls in the corners outside the plotting ring. Enabling Blizzard quest areas gives the surface rounded-square corners so their map shapes fit; disabling quest areas restores the circle. Distance rings remain circular. Drag the surface to move it, including down to the screen edge, and adjust **Radar Scale** under Layout. Blizzard's quest-area clip sits four pixels inside the rounded surface. Explore → Route → **Walk Paths** can record a bounded, simplified walk and save it as a reusable route.

Focusing a vignette opens a small rounded card beside the radar with its name and distance. **Show All** clears the focus. The first time the radar appears, a short visual guide explains bosses, rares, treasures, quests, saved notes, and quest areas; reopen it from **How To Read The Radar** in Radar Settings.

Click the small **N** compass button to switch orientation. A small chevron tucked above your center dot and a short line show your facing. When the button is highlighted, north stays at the top and that cue turns as you turn. Click it again to restore the default facing-up radar. This choice is saved, applies to the small launcher too, and is also available as **Keep north at the top** on the Layout tab.

The small eye icon in the footer controls automatic fading and hiding. When it is bright, the radar and launcher stay fully visible both in combat and inside instances, and an empty radar stays open through zone or phase changes. It overrides **Hide when empty**, including while map data is temporarily unavailable. Click it again to allow automatic fading and hiding. The setting is saved and also appears as **Stay fully visible** under Behavior. You can still close the radar yourself or disable tracking. Alert muting remains a separate choice.

The short trail-mark icon in the footer is a quick travel-trail switch. Left-click to show or hide the trail; right-click to open a scrollable picker with animated examples of twelve styles, including filled and hollow squares. Choosing a style turns the trail on. The same picker opens from **Styles & flow** in either Explore settings panel. Marks now stay anchored to the route you actually walked, including turns; Flow moves a soft highlight across them instead of sliding and restarting the whole strip. Long pauses, teleports, and instance changes break the path so a false straight line is not drawn. Spacing sets the gap between marks (50–200%); low values can overlap marks into a nearly continuous trail. Size accepts 10–200%. Flow runs from Still through 0.25×, 0.5×, 0.75×, 1×, 1.25×, 1.5×, 2×, 3×, and 4×. **Fade (seconds)** controls how long recorded marks survive. **Fade amount** accepts any whole percent from 0–100 for how dim the oldest marks become; **Faded part** accepts 0–100% for how much of the visible trail tapers. The examples update immediately. These choices are saved. Dashes remain the default so the trail reads differently from quest diamonds.

The full radar supports 10, 25, 50, 100, 150, 300, 450, 600, 1,200, 2,400, and 4,800-yard radii. Scroll down over it or click the borderless `−` icon to zoom out; scroll up or click `+` to zoom in. The `N` icon toggles north-up and glows when locked. Zoom, compass, focus, legend, and close controls use the same circular hover cue as the eye and settings dot. The range readout is the distance from you to the outer range ring. The launcher stays at 150 yards. Optional **Smart zoom** widens the view while moving quickly and chooses a close range around a focused target. Manual zoom takes control for 30 seconds.

In **Guides**, **Ring visibility** controls the circle lines and **Yard text visibility** controls the two in-radar yard labels. Existing characters start with the label opacity matched to their current rings; either setting can then be changed without affecting the other. The footer range readout stays readable.

Open the **Explore** tab in either settings panel for smart zoom, marker spreading, the travel trail, approach alerts, journal recording, distance, and hunting presets. **Saved presets, pins & journal** opens the management panel for named presets, pins, routes, and history. `/vr explore` remains an optional shortcut to that panel. Its five pages keep optional hunting tools off the radar face:

- **Modes:** Treasure, Rare, Questing, and Exploring presets change the range, layout, and filters together. Save up to eight named presets with your current colors and appearance; click a saved preset to load it or right-click it to delete it.
- **Tools:** Smart zoom, crowded-marker spreading, a travel trail, watched-target approach alerts, and the sightings journal can be switched independently. Set the approach distance from 25 to 600 yards. Watch or unwatch a live detection with Ctrl-Alt-click; entering the chosen radius pulses it and plays a sound when the existing alert-sound setting is on and alerts are not muted.
- **Route:** Preview three to five nearby quest locations, live treasures, and saved pins before applying the draft. Choose a 300, 600, or 1200-yard radius. Distances are straight-line yards, not walkable paths. Previewing does not change the saved route.
- **Pins:** Give your current location a name with **Add pin** or `/vr pin <name>`. Pins are saved and shown as gold dots on the same map once you move clear of the player marker. Click one to add a route stop or right-click it to remove it. The Pins page also lets you add or delete saved pins.
- **Journal:** When enabled, keeps the last 100 first sightings with their map coordinates and time. The journal records what the game exposed, not whether a creature was killed or loot was taken.

Ctrl-click a live detection or click a saved pin to add it to an eight-stop route. Numbered stops and connecting lines give straight-line guidance; **Next** advances, **Back** restores the previous stop, and **Undo** reverses the last route or pin edit. Routes and pins are saved; the 20-step Undo history lasts until logout. Stops from another map remain in the queue and appear when you return to that map. The optional trail records recent movement only in memory. It uses a bounded pool of at most 64 marks, or 48 for the four-stroke diamond style, and keeps the newest part visible first.

When detections overlap, a single marker shows a count; hover it to spread the individual markers briefly, then choose one. Turn this off in Explore tools if you prefer every marker drawn at its exact position. Quest diamonds and hovered quest areas show the quest name, unfinished objective text, and completion count when Blizzard provides it. Click a quest diamond or area to spotlight its quest; click it again to clear the spotlight. Other quest areas stay visible. Right-click the radar legend button, or use **Toggle quest key** on either Quests settings page, to show a scrollable quest key to the radar's left. Each named diamond matches its quest-key row. Hollow diamonds mean a quest is in progress; filled diamonds mean its objectives are complete and it is ready to turn in. Quest-area shading is blue by default; **Match areas to diamond colors** in Quests settings colors exact blobs and estimated circles to match the diamonds. This optional color mode uses solid TGA files and requires a full game-client restart after installing this version. Click a row to spotlight that quest. Suggested group size appears on vignette tooltips when Blizzard supplies one.
The quest key also shows compact objective progress (for example, `2/4`) beside each quest name; hover a row for unfinished objective text. Disable **Progress** on the Quests tab if you prefer names alone.

In the radar legend, the four live-type rows can spotlight a whole category: click the row to dim other shown live types, or click it again to clear the spotlight. The separate **ON/OFF** button only shows or hides that type. **CLEAR** removes the spotlight without changing visibility. Map notes and the remaining symbols below are a reference key; use the Quest Key to spotlight a particular quest.

Optional edge cues mark the direction of up to six already-known rares, treasures, or quests just beyond your selected range; they never scan for new targets. Hover a cue for its name and distance. **Outline tracked quest** brightens the diamond border of Blizzard's supertracked quest without spotlighting or hiding other quests; the radar only spotlights a quest you click. Hover the full radar's empty count, or use the square view's corner help control, to see why nothing is showing and where to adjust filters or map data.

The **Wayfinding** tab adds optional Blizzard next-step waypoints, available quest-line start badges, numbered quest diamonds, a map-data status explanation, and a hold-to-filter lens. A next-step diamond moves only when Blizzard supplies a waypoint on the current map; otherwise it keeps the quest location. Start badges distinguish campaign and important quests and show above/below hints when supplied. Numbered diamonds match their quest-key rows. Click **Data status** to see why quests, blobs, or map-pack notes may be missing. Enable **Explain missing map data** to make the full panel status line hoverable even with detections present. Enable the hold-key option, choose Quests, Rares, or Treasure, then assign **Hold to filter radar** under WoW AddOns key bindings; releasing restores the saved view. **Draft route** opens the Route page. Optional **Advance route on arrival** moves to the next stop after you enter a 10, 20, or 40-yard arrival radius; the Explore panel's **Back** button restores the previous stop. It waits for an outside-to-inside crossing so loading beside a stop does not skip it. These navigation extras are off by default.

The optional **Bearing Bar** is under Quick settings → Markers → **Bearing Bar...**. It puts themed rare, boss, live treasure, selected map-pack treasure or cave-entrance, and quest-point bearings in a draggable screen-space display; quest blobs are never included. Choose marker categories independently, a 150–2,400-yard range, and up to 4, 8, 12, 16, or 24 points. Nearby points in the same direction share one marker with a count and a hover list; right-click to cycle them. Favorite notes receive priority, and the current waypoint gets a small underline. Hollow quest diamonds are in progress, filled diamonds are complete, and matching live detections take precedence over saved map notes. Click a bearing to focus it; Shift-click to set a Blizzard waypoint. The bar is off by default. It does not place multiple floating markers in the 3D world, and it works without WaypointUI.

**Status → Rescan Now** refreshes map-pack data immediately when a pack loads or changes. **Status → Performance...** offers Standard, Balanced, and Low CPU update rates. The radar caches quest scans and blob geometry, skips unchanged chrome, and throttles trail drawing; Status reports its recent measured workload in milliseconds per second. Sustained high workload temporarily reduces update frequency; the selected rate returns after a quiet period. Extreme spikes pause the affected updater briefly, then retry automatically at Low CPU speed with increasing cooldown if the load continues. Neither recovery needs a reload. The addon also exposes bindable actions in WoW's **Key Bindings → AddOns → Magpie** for the radar, settings, Bearing Bar, Auto Route, current Zygor step, nearest Closest/Rare/Treasure/Quest route, and clearing focus.

World-map detections are included by default and can be disabled on the Radar settings tab. Only publicly exposed, unfogged map entries with usable positions are included; tooltips identify their source. Changing this option clears incompatible last-seen markers and seeds the new view silently. Increasing the displayed radius cannot make Blizzard supply hidden or unloaded spawns, so there is no guaranteed detection distance. The addon maintains up to 256 current/last-seen entries and draws up to 64 at once; crowded views show an explicit count and individual entries remain available in the target picker.

## Constellation HUD

The orbit icon in the radar's upper-right corner opens a transparent, centered spatial map. Right-click it for a dedicated **Show / Looks / Layers / Direction** popup with plain-language explanations. Choose **Live Only**, **Map Pack Only**, or **Mixed**; adjust icon size and visibility, sphere size and position, range rings, globe lines, bases, trail brightness, readout visibility, the center steeple, facing line, guidance, and reduced motion. The Show tab also lets you choose Ctrl, Shift, Alt, or Off as the key for interacting with icons. Hold that key to hover for a tooltip or click an icon to focus it; otherwise the map is click-through. The compact Radar Settings → Markers → Constellation page remains available. You can assign **Toggle Constellation HUD** under Key Bindings → AddOns → Magpie. The HUD is off by default and keeps working when the radar panel is minimized.

Live Only shows current eligible detections. Map Pack Only shows possible locations from the selected map-data source. Mixed shows both, replacing a matching saved point with its live version while detected and restoring the saved point when it disappears if still eligible. The hollow base identifies a saved location; a filled center identifies a live one. Icon names appear in tooltips rather than beside every icon. Focusing an item on the radar highlights its counterpart in the constellation immediately. A selected destination receives a bounded animated ant trail through explicit approach steps when available, or a straight **Direct Bearing** otherwise. A tiny center dot, attached steeple, and short line show your facing, including when North Up rotates the map. The sphere uses horizontal map coordinates and character heading; its decorative stems do not represent object height or terrain-safe navigation.

## Install

Copy the `Magpie` folder to `_retail_/Interface/AddOns/`, then reload the game. Waffle House, EllesmereUI, and HandyNotes are optional; none is required for the radar to work. If Waffle House is installed, existing radar settings and positions are copied into Magpie's own SavedVariables on first load.

## Commands

- `/magpie` toggles the radar. `/vr` works too.
- `/vr on`, `/vr off`, and `/vr preview` control visibility.
- `/vr recenter` brings a hidden or off-screen radar back into view and resets its saved positions.
- `/vr config` opens the addon settings.
- `/vr explore` opens Explore tools; `/vr pin <name>` saves a pin at your current position.

The addon also appears under the game's AddOns settings when the current Retail Settings API is available.

## Detection and navigation

- New rare and treasure detections pulse briefly. Sound is off by default; enable it and select categories or a repeat cooldown under `/vr config` → Alerts. Initial login/zone scans are silent, and rapid changes are throttled.
- Click a marker or target-list row to focus it; click it again to show all. The focused readout shows its name, distance, direction, and rare health when the game supplies it. A rim arrow points toward a live focused target outside the selected range.
- Shift-left-click a live marker, row, or focused readout to activate Blizzard navigation. A supported map waypoint is used if direct vignette tracking is unavailable.
- Alt-left-click to toggle a saved favorite. Favorites have a star, sort first, and use a distinct sound when sound alerts are enabled.
- Right-click to ignore a vignette for the current login session. Shift-right-click saves that ignore across logins. The Behavior page can clear both lists. Favorites and ignores apply to a vignette type when Blizzard provides a stable ID.
- Lost detections become fading hollow markers for 10 seconds by default. They are explicitly labeled as last seen, cannot trigger live navigation, and expire automatically. Zone changes clear them.
- Rares use silver-blue skulls; confirmed world bosses use larger red skulls. The small launcher also says `RARE` or `BOSS` for nearby live enemies. Target rows and tooltips spell out the type, and both enemy types use the Rare / Boss filter. Boss identification uses Blizzard's reward-quest metadata; unavailable metadata keeps the normal rare treatment rather than guessing.
- Treasures and other detections use Blizzard's own icons when available, with simple fallback markers. Marker size and recognizable icons are configurable.
- Optional quest diamonds use quest positions supplied by the game. When Blizzard supplies several positions for one quest, each distinct objective location gets a diamond while the quest key and count still show one quest. A watched quest with no usable map record can fall back to Blizzard's current-map objective waypoint. Blizzard does not expose coordinates for every written objective, so text alone cannot create a reliable dot. **Color quest diamonds** assigns distinct marker colors to up to eight current quests, reusing colors when more are present; a dark border keeps each diamond separate. Exact Blizzard quest shapes and approximate circles stay blue regardless of diamond color. The single native blob frame retains its shape between radar redraws. Quest updates invalidate it immediately; a backed-off safety retry checks for late Blizzard geometry without redrawing it every frame. Close zoom keeps exact areas visible on a bounded canvas and fades both kinds of shading as the view narrows, so a large area does not obscure markers. In the square quest-area view, **Approximate quest circles** adds a soft, clipped circle behind each diamond, including quests without a Blizzard area. The setting has 10, 20, 40, and 80-yard radius choices; a tiny radius is enlarged on screen at wide zoom so it remains visible. These circles are visual estimates, not Blizzard objective boundaries. Map projections retry when initially unavailable, and quest shapes redraw on quest updates with a safety retry that backs off to 20 seconds so late data can appear without changing zones or reloading. Hover a diamond or shaded area to see its quest name and unfinished objectives.
- Combat fading, combat alert muting, and instance quiet mode can be adjusted under Behavior. Instance quiet mode mutes alerts and fades the radar and launcher unless **Stay fully visible** is enabled.

Preview samples support focus without changing favorites, ignores, or navigation. All live information still comes from Blizzard's exposed vignettes; the optional HandyNotes layer is saved map information and does not by itself determine whether a location is active, killed, or looted.

Confirmed treasure loots, nearby live-rare death or reward transitions, and watched quest objective progress save bounded player-at-event observations. The addon records map XY and, when the client exposes a matching UnitPosition, height; these are not exact object or NPC coordinates. Rare samples stay alongside their original spawn pins rather than moving a known pin to where the player stood. After two nearby completions, Use Learned Objective Hints can guide an unmapped objective; its diamond tooltip identifies the approximate source. With WaypointUI installed, Smooth Pin eases brief screen jumps of Magpie's own floating waypoint while preserving its map destination. Both options are on by default.

## Development validation

Retail 12.1.5 support: interface `120105`, checked against Blizzard's UI/API export for build `70391`. Map, quest, vignette, and area POI APIs retain the signatures Magpie uses.

Current development build: `0.1.0-dev.115` (base version `0.1.0`).

If Quest Auto Route waits, `/vr route debug` reports cached point counts without starting a scan. The mini arrow's three "Next (Preview)" entries are a preview, not the complete route. The broad current-map quest-log scan from dev.94 remains disabled after its in-game hang.

Repeating launcher, radar, and idle updates have a session-only CPU guard. A stalled update, or three consecutive slow updates, pauses that repeating work and prints a chat warning. `/reload` retries it.

Run each `tests/*_test.lua` with Lua from the addon root and check Lua files with `luac -p`. The tests cover migration, radar projection, filters, target actions, alert/last-seen state, navigation fallbacks, quiet modes, mouse-wheel/button zoom, world-map visibility guards, and UI layout bounds using mocked game APIs. Layout checks exercise repeated style changes, automatic Squat details, focused and unfocused states, edge and corner resizing, pop-outs, resized rings and markers, and an 800×600 canvas. Orientation checks cover quarter turns, fixed markers/cardinals, the player direction line, both radars, preview, unknown facing, and out-of-range focus. These checks do not replace in-game validation of rendering, navigation, or API availability.

## Source Layout

Lua source is grouped in `Core/`, `Data/`, `Routes/`, and `UI/`. The `.toc` lists every file in its required load order. Keep `Bindings.xml` at the addon root so WoW loads it automatically; assets stay in `Media/`, with local checks in `tests/` and generators in `tools/`.
